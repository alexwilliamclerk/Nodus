# Nodus 使用手册

[返回首页](../README.md) · [开发指南](development.md)

**从一个想法出发，改变世界**

Nodus 是以动态选项为核心交互的 AI 桌面工作台，支持 Windows、macOS 和 Linux。你可以用自然语言发起任务，通过选项明确需求，或授权 Agent 自主制作；应用将任务规则、执行、作品预览、手动评分和版本管理连接起来。

产品聚焦两个方向：**用户要求的持续守护**与**有证据的完成验收**。当前提供独立保存的任务规则、内置守护 Skill、执行权限控制、文件验证和模型辅助审查。它帮助用户查看实际交付及未验证事项，不承诺识别模型的主观意图或杜绝遗漏。

## 主要功能

- **动态选项**：根据当前任务和已提交的选择逐题细化，支持单选、多选、逐项补充及自由输入。
- **两种工作模式**：默认 `/plan` 先规划、确认后制作；`/goat` 在授权范围内自主规划、制作和检查。
- **回看与反悔**：返回上一题恢复选择和补充；修改上游决定后，相关下游结论失效。
- **暂停后继续决策**：实际停止后选择调整、补充、继续或暂存，按当前模式重新提交后继续执行。
- **实时回复**：主对话区逐步展示模型实际输出，使用统一的半透明消息气泡。
- **中途预览**：设置中为当前任务选择每 3、5、8 次已提交修改制作一版，完成后自动打开预览并等待评分。
- **预览与评价**：查看作品、展开预览、手动评分并发起调整；评分关联具体产物版本。
- **版本与检查**：修订使用工作副本，恢复作品创建新版本，失败文件保留在未完成目录。
- **任务规则**：首轮提交后按原文整理规则，后续追加已提交选择；支持查看来源、直接修改、停用、恢复及变更记录。
- **要求证据审查**：执行后以只读模型调用逐项核对实际文件；明确冲突不登记成功版本，缺少可靠证据的要求保持待用户确认。
- **多模型连接**：设置中添加多条 API 连接，通过对话框下方的菜单切换已接入模型。
- **备份导出**：将对话、附件、决定、评分和作品导出为 ZIP，排除应用保存的模型凭据。

## 支持的产物

| 类型 | 交付内容 | 当前检查范围 |
| --- | --- | --- |
| 网站 | HTML、本地 CSS/JavaScript 和图片资源 | HTML 结构及本地资源引用 |
| 调研报告 | Markdown 正文与来源清单 | 章节结构、来源状态及部分核实措辞 |
| 演示文稿 | PPTX 文件与幻灯片预览 | 文件解析、幻灯片关系及预览文字对应 |
| Python 工程 | Python 源码、依赖文件和运行说明 | 固定 AST 语法检查 |
| 数据分析 | CSV/JSON 输入快照、分析代码、统计结果和说明 | 应用描述统计器及输入与结果对应关系 |

任务类型按需求识别，也可手动纠正。项目分组与产物类型分别管理。暂不支持的格式或超出能力的需求需要澄清，不能自动视为已支持。

联网搜索会列出可点击的外部来源，但不会自动完成事实核实；PPTX 以文字标题、要点和备注为主；Python 不自动安装依赖或运行生成代码；数据分析目前限描述统计。完整后端、小程序、自动部署、复杂 DOCX/XLSX 版式及自由媒体排版不在当前交付协议范围内。

## 下载与安装

本地开发版本为 **v1.3.1**；已公开的最新版本以 [GitHub Releases](https://github.com/alexwilliamclerk/Nodus/releases/latest) 为准。

| 平台 | 安装包 | 安装方法 |
| --- | --- | --- |
| macOS Apple Silicon（arm64） | `Nodus-v{版本}-macOS-arm64.dmg` | [在最新发布页下载](https://github.com/alexwilliamclerk/Nodus/releases/latest)，打开后将 Nodus.app 拖入“应用程序” |
| Windows x64 | `Nodus-v{版本}-Windows-x64.exe` | [在最新发布页下载](https://github.com/alexwilliamclerk/Nodus/releases/latest)，运行安装向导并选择安装目录 |
| Linux x64 | `Nodus-v{版本}-Linux-x86_64.AppImage` | [在最新发布页下载](https://github.com/alexwilliamclerk/Nodus/releases/latest)，赋予执行权限并运行 |

历史版本的文件名可能不带版本号。新发布还会附带旧文件名的兼容副本，让旧版应用内更新按钮和原有一句话下载命令继续工作。

安装包内置 Electron 与 Pi SDK，无需另外安装 Node.js 或 Pi CLI。Python 工程与数据分析需要本机 Python 3，建议使用 3.10 或更新版本并加入 PATH。模型调用需要联网和对应服务的有效凭据。

安装包通过 GitHub Releases 分发；下载源码 ZIP 不包含安装器。

更新应用前先退出程序，可通过设置导出重要任务备份。程序文件与用户数据分别存放，更新应用不需要覆盖数据目录。

macOS 关闭窗口会隐藏窗口并保留正在执行的任务，点击 Dock 图标可重新打开。需要停止任务时使用应用内“停止”；需要结束应用时使用“退出 Nodus”。

发行包尚未完成正式开发者签名与公证。确认来源后使用操作系统提供的正常允许流程。Windows 安装器尚未完成干净系统实机验收，最低系统版本兼容矩阵尚未建立；Linux AppImage 可能需要 FUSE 运行库，尚未完成干净系统实机验收；目前没有 Intel Mac、Windows ARM 或 Linux ARM 的预构建安装包。

## 快速开始

原生菜单栏提供中文“文件”菜单：新建对话（Ctrl/Cmd+N）、打开已有对话（Ctrl/Cmd+Shift+O）、打开文件作为材料（Ctrl/Cmd+O）、保存对话（Ctrl/Cmd+S）以及备份导出（Ctrl/Cmd+Shift+S）。打开已有对话保留其草稿和版本；打开本地文件使用现有材料解析能力，不会直接覆盖源文件。macOS 的退出位于 Nodus 应用菜单，Windows 的退出位于文件菜单末尾。

1. 点击底部模型按钮，选择“管理模型连接”，或从左下“模型连接”进入设置。
2. 填写连接名称、提供商、模型 ID 和 API Key，点击“添加并验证”。可继续添加其他连接；关闭设置后通过底部菜单切换。
3. 新建对话，描述任务目标与交付格式。可通过加号、拖入或粘贴添加材料。
   输入区可选择已有项目或新建项目，并通过“选择本地目录”指定作品交付位置。项目用于对话分组，目录用于存放导出的作品；首次实际制作前未选择目录时会主动弹出文件夹选择器，取消后保留选择而不开始制作。
4. 默认 `/plan` 下核对产物类型，选择方案并补充要求。勾选仅保存选择，提交后才执行。
5. 生成后打开预览，查看文件和验证依据。可以手动评分，也可以直接发起调整。
6. 按动态问题确定修改范围；可随时点“确认已选修改并预览…”结束提问。确认执行后才生成新版本，右侧预览随后更新；在选择阶段看到的仍是上一版本。

满意时点击评价区的“接受 Vn 并结束”，无需先打分，也不会继续自动修改；希望迭代时选择“提交评价，继续改进”。接受操作记录所选版本，但不会把未验证的条件改成通过。

同一版本重复接受不会追加相同消息；评分和意见未变化时不重复提交或调用模型。调整过程中可点击“返回作品”保存当前选择并回到作品／评价界面，再次点击“调整”可继续之前未完成的选择。接受交付会结束未完成的调整，返回操作本身不授权制作。

制作完成后，作品自动复制到所选目录中的独立任务版本文件夹，主对话显示实际路径。点击“打开目录”可在 Finder／资源管理器访问文件；“导出作品”可另选位置导出当前查看的版本。接受交付后这两个入口仍然保留，文件菜单也提供相同功能。网站导出包含本地资源，PPT 导出包含真正的 PPTX，其余类型保留代码、说明和相关数据。重复导出新建文件夹，不合并或覆盖已有文件。

应用内的版本副本仍然保留。交付目录不可用时会明确显示导出失败，作品不会因此丢失，可重新选择目录导出；失败的制作文件不自动导出为成功交付。项目和目录选择会随任务保存，切换项目不会移动此前导出的文件。

### /plan 与 /goat

| 模式 | 使用方式 | 执行行为 |
| --- | --- | --- |
| `/plan`（默认） | 直接输入需求，或输入 `/plan 任务目标` | 先生成四个方案，用户选择、补充并提交后才制作 |
| `/goat` | 输入 `/goat 任务目标`，或在当前任务中提交 `/goat` | 自主规划、采用推荐方案、制作、检查，并在可修复时继续尝试 |

```text
/plan 创建一个个人作品集网站
/goat 根据附件 CSV 生成数据描述统计报告
```

模式选择器位于输入区底部的模型按钮旁边，只切换模式，不会立即执行。命令支持需求输入框、选项补充框和临时对话；只识别消息开头，不把正文中的命令名称或路径当成操作。Agent 自主采用的推荐单独记录，不冒充用户手动选择。

`/goat` 每次提交最多进行 **3 次制作尝试**，不是无限运行。校验失败会沿用未完成文件修复；缺材料、连接或环境不可用、达到上限时报告卡点。文件通过但目标仍需人工判断时进入评分验收，不宣称目标全部完成。用户可随时停止，重启应用不会自动恢复付费调用；工具与产物能力边界保持不变。

### 选择与自然语言

在设置中选择“当前任务的预览节奏”，可授权每 3、5、8 次已提交修改后自动制作一版（会调用模型），也可保持默认“手动确认后生成”。设置只影响当前任务已有作品的修改；从启用时开始计数，普通答疑、暂停菜单和未提交草稿不计数，返回改选会相应减少当前有效计数。每版通过现有验证后自动打开右侧预览并停在评分处，主对话列出本轮修改范围；失败时保留原版与未完成文件。重新打开任务不会仅因达到次数而自动执行，仍需提交操作。

临时对话每次一问一答，结束后返回原操作并保留草稿。任务可置顶、重命名、归组、归档或从导航删除；从导航删除不会连带删除作品文件。

空白任务可以直接聊天，无需先填写需求或选择类型；需要制作作品时再手动触发类型识别与规划。生成、修订或自主制作完成后自动打开作品预览，内部要求审查 JSON 不进入主对话，检查结果通过“查看依据”阅读。

常规修改默认在两项已提交选择后进入执行确认；也可更早点击“确认已选修改并预览…”。这一步只展示已选范围，不会立即调用模型修改文件；用户仍可返回调整、继续细化或暂存。设置了每 3、5、8 次修改自动预览的任务继续按已授权的节奏执行。网页修订会检查站内跳转目标；未选择修改交互时，也会阻止新版本删去原有导航和交互入口。脚本的实际行为仍需在预览中试用。

选项框也可以直接提问或用自然语言回答。提问不会被登记成制作要求；“第二个”“前两个”等回答会对应到当前选项并检查单选、多选限制。返回、暂存等明确操作优先处理。意图识别失败时保留输入，可重试或继续使用选项按钮。自然语言理解依赖当前模型，不能保证任意表达都准确识别，执行前应核对确认范围。

## 任务规则与交付依据

### 任务规则

首轮提交后，应用按原文段落整理目标、禁止事项、保留项及其他约束，保存为独立的任务规则。已提交方案和最终确认的修改随后追加，验收条件保留其来源。当前采用原文整理与简单分类，不让模型擅自重写标准；复杂、混合表述需要用户核对。

规则随每次规划、答疑、意图识别、执行和审查请求作为**用户级任务数据**提供，不升级为 system rule。普通问答独立保存为背景；未选择方案、未提交草稿和返回后失效的分支不成为规则。

在“任务要求”中可查看来源及状态，通过“修改规则”直接替换当前文本，也可停用或恢复条目。旧文本保留在变更记录及原产物版本中，后续调用使用当前有效规则。尚未明确解决的矛盾仍需澄清；编辑展示规则不会自动关闭已配置的确定性检查。

### 完成条件与守护 Skill

方案阶段可通过“完成条件”填写要求。普通文字条件保持“需人工确认”；完整整数序列可设置起止值及相对文件名，由程序逐项检查数量、顺序和遗漏。

普通制作中主动授权后，确定性条件检查失败可触发最多一次补齐；`/goat` 使用自身的 3 次尝试上限，不叠加这项补齐次数。文件变化会在加载检查证据时使相关结果失效。文件校验通过、用户评分和用户接受交付是不同信息，不应相互替代。

单个版本的完成记录不可读取时，该版本显示未验证并保留原始记录，不阻止其他任务和可用作品的访问。涉及该记录的修订或恢复不会跳过原完成条件直接登记成功。

Nodus 内置 `nodus-requirement-guardian` 系统 Skill，并在每个 Nodus Agent 会话中强制加载。Skill 约束模型不得静默缩小范围、用示例或省略号替代完整交付、把说明文字冒充实际修改，或在受限时宣称完成。若 Skill 缺失或无效，运行时拒绝启动 Agent 会话。该机制只作用于 Nodus 内嵌运行时，不会越权安装或修改用户电脑上的其他 Agent 产品。

产物通过文件及确定性检查后，会增加一次只读要求审查模型调用。该审查必须引用实际产物文件中的逐字片段才可标为“文件证据支持”或“明确冲突”；模型审查仍可能误判，因此它与确定性验证分开显示。涉及视觉观感、实际运行或文件快照无法证明的要求保持“待用户确认”。强制加载 Skill 只能保证规范被提供给模型，不能保证模型完全遵守。

## 材料与预览

单文件上限为 20 MB，提取文字上限为 128 KB。支持文本、常见代码、PDF/DOCX 文字，以及 PNG/JPEG/WebP 图片。PDF/DOCX 不包含 OCR、嵌入图片理解或版式还原；图片需要支持视觉的模型。输入网址不代表应用已访问网页。

右侧预览栏可展开至整个应用内容区，再通过还原按钮或 Esc 返回。展开不重新加载作品。主对话显示解释与执行信息，底部只保留当前输入、选项、评分和操作控件。

对话默认跟随最新内容，并在消息增长、输入区或窗口尺寸变化后保持到底部。主动上翻阅读历史时暂停跟随，可点击顶部“回到最新”恢复；提交新的用户消息也会恢复跟随。

## 界面语言

在“设置与模型连接”的“界面语言”中选择“简体中文”或“English”。切换后主界面、设置和原生菜单立即更新，重启后保持选择。已有对话、用户材料、任务规则和作品文件不被自动翻译；后续新生成的动态问题与选项会根据所选界面语言输出，交付文件语言仍以任务要求为准。

## 外观主题

在“设置与模型连接”中选择“浅色”“深色”或“跟随系统”。切换后界面和原生菜单立即更新，选择会在重启后保留。已有数据默认沿用浅色；作品预览保留作品自己的配色。

## 应用更新与卸载

在“设置与模型连接”中点击“检查更新”，Nodus 会读取官方 GitHub Releases 的最新版本。Windows 安装版和 Linux AppImage 版如果具备匹配的自动更新元数据，下载后会核对 SHA-256，再经用户确认安装并重启；有运行中任务时不能启动安装。Linux 可以勾选删除旧版 AppImage，或取消勾选并在原目录留下旧程序备份。Windows 在原安装目录升级会替换旧程序文件；安装向导仍可让用户选择目录。元数据不可用时，可下载已校验的安装包并按向导更新。macOS 的更新按钮会打开对应版本的 GitHub 发布页；下载 DMG 后在 Finder 将 Nodus 拖入“应用程序”，选择“替换”即移除旧应用程序文件，不会删除任务数据。当前已是最新版时仍可重新下载安装包用于修复本地安装。

Windows 已安装版的设置页提供“卸载应用…”入口。卸载时会先确认并退出应用，任务与作品数据默认保留。如果本机 `Uninstall Nodus.exe` 弹出 NSIS 完整性错误，请查看 [Windows 卸载修复说明](windows-uninstall.zh-CN.md)，不要跳过校验或关闭安全防护。

提供商、地区与产品凭据必须匹配。Kimi 开放平台 Key 与 Kimi Code 凭据不能混用；开放平台连接先查询账户模型列表，再选择已适配的可用模型。指定模型时使用完整 API ID，不填写产品简称。

同一提供商可添加多条连接，支持自定义名称和移除单条连接。切换目前为应用级行为，任务运行期间不可切换。

Windows 或其他系统上如果输入框的 Ctrl+V 没有响应，可点击 API Key 输入框下的“从剪贴板粘贴”；应用通过桌面剪贴板读取并只填入当前表单，不写入任务记录、聊天记录或日志。

模型连接面板仅展示本机累计 Token 用量及已记录的响应次数，汇总所有任务和模型的记录。没有记录时显示“0 Token／暂无已记录的模型用量”，不表示账户从未使用。应用不提供费用估算、套餐余额查询或余额占位展示。

默认密钥只在本次运行内存中使用，退出后需重新填写。主动勾选“在本机记住连接”时才加密保存。macOS 启动不自动访问钥匙串，已保存连接通过“恢复已保存连接”主动加载。拒绝钥匙串授权不应影响仅本次使用模式。

联网搜索在设置中单独配置。复用当前 Key 支持 OpenAI、Anthropic 与 Qwen 百炼模型连接；也可以用独立的 Brave、Tavily、Qwen、OpenAI 或 Anthropic 搜索 Key。独立 Key 默认只在本次运行使用，可选择本机加密保存。对话中的“联网搜索”会把网页标题和链接加入当前对话，作为后续模型答复的外部资料；来源与摘要可能有误，不能视为自动事实核实。搜索调用可能消耗服务商额度。

连接验证只证明一次文字请求能够返回，不证明所有模型、工具或视觉能力均可用。不同账户的权限、余额和模型可用性以服务商为准。MiniMax、Qwen 等入口尚未完成逐一真实账户验收。Qwen 当前使用保守文本配置，DeepSeek 的上下文/输出预算亦不代表服务商最大容量。

## 数据与备份

默认数据目录：

- macOS：`~/Library/Application Support/Nodus/forma-data`
- Windows：`%APPDATA%\Nodus\forma-data`

可使用 `NODUS_DATA_DIR` 指定独立目录。任务、附件及作品以 JSON 和文件保存；只有主动保存的模型凭据使用系统加密。材料会发送给所选模型服务，本机优先不表示模型离线运行。

```text
forma-data/
  state.json                      任务、决定、评分、版本和设置
  credentials.json                加密保存的模型连接
  pi/                             模型与运行配置
  artifacts/<task>/<version>/     作品文件
  artifacts/<task>/.pending-*/    未完成工作
  artifacts/<task>/.completion/   完成检查证据
```

在设置中点击“备份对话并导出”，选择应用数据目录之外的 ZIP 保存位置。导出前会保存草稿，运行中的任务需先停止。备份包含归档及导航隐藏的对话、附件、评分、作品和未完成文件，排除应用凭据及 Pi 认证目录；缺失文件会在备份清单中说明。

ZIP 内附恢复说明。恢复前退出应用并备份目标目录，按说明使用独立数据目录或恢复文件；目前没有应用内导入功能。跨电脑需要重新添加模型连接。用户自行写入对话或作品的敏感文本不会被自动识别清除，备份应按私人数据管理。
